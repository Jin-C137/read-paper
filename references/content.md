# 内容契约

## 必备与自选

| # | 标题 | |
|---|---|---|
| 1 | Motivation：论证链条与 research gap | 默认必备 |
| 2 | Literature review：别人做到哪一步 | 默认必备 |
| 3 | 模型全貌：论文的核心形式化对象 | 默认必备，本笔记的主体 |
| 4 | 算例设置与主要结论 | 默认必备 |
| 5 | 建模贡献在哪里（含我的评估） | 视论文 |
| 6 | 存疑点与需要核实的地方 | 视论文 |

第 3 节的"核心形式化对象"随论文类型变：优化论文是变量 / 目标 / 约束，
ML 论文是网络结构 / 损失函数 / 训练流程，实证论文是回归设定 / 识别策略，
理论论文是假设 / 定理 / 证明骨架。**按论文实际的形式化方式写，不要套优化问题的框架。**

**「默认必备」不等于无条件必须**：原文确实没有对应内容时（Letter 常无独立 literature review、
纯理论文无算例、综述无模型），写一句「原文无此节」并交代替代内容即可。
硬凑一节空话违背下面的「没发现就不写」。

**自由度**：这份笔记服务于「读者不看原文也能弄清这篇在干什么」，章节是手段不是目的。
论文若有特别值得单独成节的东西（复杂的求解方法、一套值得借鉴的实验设计、
与用户当前课题的具体关系、数据集来源的坑……），就加一节；反之则合并或省略。
判断标准只有一条：**这一节是否让读者少走一段弯路。**

编号与目录随实际章节数调整，不要留空节，也不要为了对齐模板保留无内容的标题。

## 1. Motivation

- 把作者的论证链条还原成一条**流程图**（`.dgm`），每步一个盒子，按原文的推进顺序走。
- 逐条列出 research gap，每条一张 `.card`。
- 若作者的写法本身值得借鉴（比如「先给对方台阶、再指出边界」的节奏），单开一个 `.box.ok` 记下来。

## 2. Literature review

- 若原文有综述对比表，**逐格复刻**，最后一行 `class="hl"` 放「本文」。
- 再补一张**逐篇一览表**：文献号 / 标题与出处 / 原文的归类 / 该文的着眼点。
- 这两张表都是查阅型，**一律套 `.fold` 折叠壳**（该套哪些表以 rendering.md 为准），
  表的小字注与「待核实」警示放进壳里一起收。
- ⚠️ 「该文实际做了什么」若只据标题与被引方的归类推断，必须整表标注**待核实**，
  不能当定论。**生成本笔记时标注待核实即可，不要求逐篇回源**；
  这些文献日后要写进用户自己稿子的 related work 之前，才必须回源确认 —— 把这句提醒写进笔记。
- 最后把表压成结论，通常 3–5 条，内容需要可增减。

## 3. 模型全貌（主体）

每组公式的顺序固定：**符号释义 → 公式 → 直觉**。

- 开篇先给**符号身份图例**（六型，定义与非优化类论文的退化规则见 rendering.md；
  只列这篇论文实际用到的几型）和全节通用的索引集合表。
- 原文若有符号撞车（同一字母多用），**开篇就警示**，这是读者最容易绕晕的地方。
- 原文的公式若靠**编号**（流股号、节点号、设备号）来写，先补一张**编号对照表**，
  否则读者看不懂式子。
- 上面这些「介绍符号是什么」的表 —— 身份图例、索引集合表、编号对照表 —— 都是查阅型，
  **一律套 `.fold` 折叠壳**，只有三四行也照套（该套哪些表以 rendering.md 为准）。
- 每组公式：
  - 先用 `.gloss`（`<details ... open>`）定义该组**首次出现**的符号，写清含义；单位与算例取值原文给了才写
  - 再给公式，标记与排版规则见 rendering.md
  - 最后每条实质性公式配一段 `.intu` 直觉（纯代数过渡式可合并或不写）
- 有约束集的论文，约束用表格列出：式号 / 类型 / 约束 / **直觉：这一条在管什么**（最后一列不能省）。
- 分上下层 / 主从问题的，先画一张 `.dgm` 说明谁向谁传什么。

## 4. 算例设置与主要结论

- 设置：这份清单是优化仿真的口径（系统 / 时间分辨率 / 数据来源 / 参数 / 求解器与硬件 / case 设计），
  **按论文类型取舍**：ML 论文换成数据集 / 划分 / 超参 / 算力，实证论文换成样本 / 时间跨度 / 变量口径。
- 主结果表照录，关键行 `class="hl"`。
- 把结论压成若干条**可复用的表述方式**，注明哪条是作者的 selling point。
- 作者自我设限的话（承认方法有物理上限之类）要保留 —— 这类句子写得得体，值得学。

## 5. 建模贡献评估（视论文）

- 先如实列出**作者自述的贡献**。
- 再给**你自己的评估表**：条目 / 评级 / 理由。评级要敢下判断（最强 / 实用 / 最弱）。
- 发现「自称的贡献名不副实」时，用 `.box.bad` 单独讲清楚，并给出证据（哪条式子、哪个参数表）。
- 不确定的地方标注置信度，不要为了显得有洞察而硬下结论。

## 6. 存疑点（视论文）

读的时候发现的不自洽、疑似笔误、摘要与正文矛盾、量纲对不上、参数表与公式冲突。
每条给出：**现象 → 推断 → 置信度 → 对本课题的影响**。

真发现了，这一节的价值常常高于前面所有节。举例：把算例温度代进 COP 拟合式，
发现单调性与物理直觉相反，从而判断该符号在两处含义不同 —— 这种发现只有真的把数代进去才有。

**没发现就不写。** 硬凑几条无关痛痒的「存疑」比不写更糟。

## 写作风格

- 精简，句子短。
- 中文为主，术语保留英文。
- **区分「原文说的」和「我推断的」**，后者一律标置信度。
- 数字照录，不四舍五入，不脑补单位。
