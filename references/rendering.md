# 渲染规则

CSS 已定稿在 `assets/template.html` 的 `<style>` 里，**不要改**
（唯一例外：用户指定了非默认配色时，按 `palettes.md` 整块替换 `:root`，其余 CSS 一律不动）。
**HTML 写法以模板 `<body>` 里的示例为唯一来源** —— 那里每个组件都有可直接照抄的骨架。
本文件只讲 CSS 和示例看不出来的**规则与理由**。

## 全局

- **区块字体一律继承正文，禁用任何等宽字体。** 理由：Cascadia/Consolas/Menlo 都不含汉字，
  中文会掉到浏览器的等宽回退（Windows 上通常是宋体），与正文黑体撞字体类别，非常扎眼。
  自检脚本里有对应 assert 强制。
- 区块字号统一 `--blk: 15px`。**区块内部的小标签不得比该区块的正文小** ——
  「直觉」这种标签用 10px、正文用 14px 是不可接受的。
- `h2` 前的序号用 `--fg`（黑），不单独染色。

## 模型章节的顺序

**符号释义 → 公式 → 直觉**，不要颠倒。

先让读者认识符号，再看公式，最后才是解读。反过来（公式在前、释义在后）会逼读者
在不认识符号的情况下先读一遍公式，再回头对照，等于读两遍。

## 符号标记（本 skill 的核心）

公式里**每一个量**都要包一层 `<var>`：`dv` / `rp` / `df` / `do` / `pm` 五态。
**徽章与公式渲染一一对应**，同一个符号在释义表里是什么色，在公式里就是什么色：

| 徽章 | 公式里标成 | 底色 |
|---|---|---|
| 决 决策变量 | `dv` | `--fill-dv`，与「决」徽章同色相 |
| 随 不确定参数 | `rp` | `--fill-rp`，与「随」徽章同色相 |
| 派生 中间量 | `df` | `--fill-df`，与「派生」徽章同色相 |
| 对 对偶变量 | `do` | `--fill-do`，与「对」徽章同色相 |
| 参 已知参数 | `pm` | 不涂底、渲染成灰字，对应灰色的「参」徽章 |
| 集 索引 / 集合 | 不包 `<var>` | 下标和求和号不是「量」 |

一句话记法：**徽章是什么，`<var>` 的类就是什么。** 只有「集」不包 `<var>`。

**不要凭「读者要不要盯住」来归类** —— 这是本节以前的写法，它把派生和对偶都并进了 `dv`，
结果释义表里紫色的「派生」在公式里是蓝底，读者会以为那是两个东西。

色值直接用 `references/palettes.md` 配好的四套，理由与改色规则都在那里。
**四支荧光笔的分离度比两支时低**：`--fill-dv` 与 `--fill-df` 的 ΔE 是
crimson-blue 7.0 / rose-lilac 7.5 / deep-blue 9.8 / teal-apricot 15.3。
**crimson-blue 与 rose-lilac 这两套里，「决」和「派生」扫读时要看仔细一点** ——
这是换取徽章/公式一致的代价，理由见 palettes.md 约束 ④。

**为什么值得花这个功夫**：标完之后一眼能看出结构性问题。比如某条 COP 公式右边全是 `pm`，
说明它在算例里其实退化成了常数 —— 这种发现光读文字发现不了。

## 直觉块 `.intu`

每条**实质性**公式配一段。讲**这式子在说什么事**、以及**它带来的建模后果**，不是复述公式。

推导链里的纯代数过渡式（换元、移项、展开、两边同乘）没有独立的"说什么事"，
**几条合并写一段、或干脆不写**。逐条硬配只会写出下面那种复述 —— 那正是本节要禁的。

- ❌ 复述：「式(1) 表示 IT 功耗等于服务器数乘以单台功耗」
- ✅ 直觉：「空载已占满载 68%，意味着**把机器闲置几乎不省电，关掉才省** —— 这决定了调度的动作形态」

## 符号释义 `.gloss`（可折叠）

符号**首次出现**时给一组释义，放在该组公式**之前**。

写成 `<details class="gloss" open>` + `<summary>`，标题写清**是哪几条式的符号 + 个数**
（`式 (1)(2) 新出现的符号 <span class="cnt">· 6 个</span>`）—— 收起后只剩这一行，个数是唯一的线索。

**`open` 必须写，不许省。** 折叠是给读者读熟之后自己收的，不是交付时替他收：

- 首次阅读时释义必须在眼前，这是本 skill 的核心价值，默认藏起来等于自废武功；
- 折叠内容在 Firefox / Safari 里 **Ctrl+F 搜不到**（Chrome 较新版本会自动展开，
  **此结论未实测，按最坏情况处理**）；
- 折叠内容**打印 / 导 PDF 时不出现**。CSS 里有一条 `@media print` 尽力展开，
  但各浏览器对 `details` 隐藏内容的实现不同，**不保证生效**。

三条合起来：**默认展开是唯一安全的默认值**，收起由读者决定。
**这三条对下面的 `.fold` 同样成立 —— 全文所有 `<details>` 一律带 `open`。**

身份徽章六型，回答的是同一个问题：**这个符号在优化问题里扮演什么角色**。
在优化类论文里，六型互斥且穷尽；其他类型的论文见下面的退化规则。

| 类 | 标 | 含义 |
|---|---|---|
| `k-s` | 集 | 索引 / 集合 |
| `k-p` | 参 | 已知参数（给定，优化器动不了） |
| `k-d` | 决 | 决策变量（要优化的） |
| `k-r` | 随 | 不确定参数（给定但随机） |
| `k-o` | 对 | 对偶变量 |
| `k-f` | 派生 | **由其他变量唯一决定的中间量** —— 优化器动不了它，但它也不是输入数据 |

判据三问：**①「优化器能动吗？」②「是外部给的吗？」③「外部给的话，确定还是随机？」**

- ① 是 → 决（在对偶问题里则是 对）
- ①否 ②否 → **派生**（如成本中间量 `C^Opr_t`、潮流 `F^line`、迭代均值 `ū`）
- ①否 ②是，③确定 → 参；③随机 → 随

只用前两问定位不了五个类：参和随同落「不能动 + 外部给」一格，靠第三问才分得开。

### 论文不是优化问题时：六型退化，不要硬套

上面这套（决 / 对 / 派生 / 参 / 随 / 集）是按**优化问题**的角色划分的。
ML 训练、实证统计、纯物理推导、综述这些论文里根本没有决策变量和对偶变量，
硬套会产出错误标注 —— 那比不标更糟。此时退化到上面那三问，只用适用的徽章：

| 论文类型 | 「决」这一格实际是什么 | 建议用的徽章 |
|---|---|---|
| 优化 / 博弈 | 决策变量 | 六型全用 |
| ML / 拟合 | 待学参数（权重、拟合系数） | 决 · 参 · 随 · 集，「对」不用 |
| 实证 / 统计 | 待估系数、检验统计量 | 决 · 参 · 随 · 集 |
| 物理 / 理论推导 | 被解出来的未知量（场、态、解） | 决 · 参 · 派生 · 集 |
| 综述 | 通常无统一符号体系 | 释义表按需要给，可整个不用徽章 |

**上表列的是典型组合，不是封闭清单。** 两个方向都要兜住：

- **表里列了、但这篇论文里不存在的型 → 不用。** 不要为了凑满六型给符号安一个它没有的身份。
- **表里没列、但按三问判据确实存在的型 → 照用。** 例如 ML 论文的预测值 `ŷ`、损失 `L(w)`，
  实证论文的拟合值与残差 —— 优化器动不了、也不是外部输入，①②都否，**就是「派生」**，
  和优化论文里的成本中间量 `C^Opr_t` 完全同构；含噪声项的物理推导同样会用到「随」。

**判据永远回到上面那三问**，它对任何类型的论文都成立；
表和判据打架时**以判据为准**。开篇的符号图例只列实际用到的几型。

**不要放进释义表的两类**（它们不是「有角色的量」，在小节开头的通用说明里交代一次即可）：

- **算子与记法**：`E[·]`、`P[·]`、`CVaR`、上划线表上限、下划线表下限
- **变量集合的名字**：`V^UL`、`V^LL`（写在 min/max 下面的那些）

> ⚠️ 注意「派生」≠ 优化文献里的「**辅助变量** auxiliary variable」。后者指为重构问题而引入的
> 真变量（如 CVaR 的 `τ`、`σ`，big-M 线性化的二元 `w`），**它们是决策变量，标「决」**。

**原文给了单位与算例取值就一并写上**，这样的释义远比只写个中文名有用；原文没给就留空，不要脑补。

## 公式块 `.eq`

- 每行一个 `.eqr`；式号放独立的 `.eqn`，靠 flex 右对齐 —— 与字宽无关，永远齐平。
- 缩进用 `style="padding-left:Nem"`，**不要用空格**（比例字体下空格宽度不定）。
- `.eqh` 纯文字小标题行，`.eqsp` 空行占位。

### 式号必须与原文一致

**照抄原文的编号，不要自己重排。** 笔记的价值有一半在于读者能拿着它回原文对照，
一旦编号对不上，正文里所有「见式 (7)」的交叉引用就全废了。三条推论：

- **跳过的公式会留下空洞，这是对的，不要为了连续而重排。**
  只讲了 (1)(2)(6)(7)(8)，编号就应该是这几个，不许压成 (1)–(5)。
- **原文怎么分组就怎么分。** 原文写 (1a)–(1h) 就照写，不要合并成 (1)。
- **原文没编号的式子，`.eqn` 留空**，不要自己发明编号。
  需要指代时在正文里用文字描述（「上面那条守恒式」），或用 `.eqh` 给个中文小标题。

## 流程图 `.dgm`

**必须是 HTML 盒子。** 绝不用 `┌─┐│` 画 ASCII 图 —— 比例字体下框线必然错位。
上下层 / 主从结构用 `.pair` 三栏（左标注 / 中箭头 / 右标注）说明谁向谁传什么。

## 提示框 `.box`

四型语义**不要混用**：

| 类 | 用途 |
|---|---|
| `.box` | 中性补充 |
| `.box.ok` | 值得借鉴 / 可以直接搬 |
| `.box.warn` | 需注意的限定条件 |
| `.box.bad` | 有问题 / 名不副实 |

## 表格

- 表头用主色浅底，正文行隔行同色，突出行加 `class="hl"`。
- **空单元格必须渲染出框**，用 `—`（`class="n"`）占位。唯一例外是合并且居中的格子。
- **含 `rowspan` 的表必须加 `class="pairs"`**。
  原因：条纹画在 `<tr>` 上，而合并单元格归属它的第一行。若按单行隔行上色，
  合并列所在位置会由上一行的透明背景透出，形成空洞。`.pairs` 改为按两行一组上色。

## 长查阅表折叠壳 `.fold`（可折叠）

**查阅型**的长表套 `.fold`：读者不是从头读它，而是读别处时回头查它。两类，**都是必套**：

| 该套 | 具体是哪些 |
|---|---|
| **notation 类** | 符号身份图例、全节通用的索引与集合表、编号 / 流股 / 变量对照表 —— 凡是「介绍符号是什么」的表 |
| **literature review 类** | 原文综述对比表的逐格复刻、逐篇一览表 |

**不套**的：算例设置、主结果表、约束一览、评估表、存疑点表、演示用的算例表。
这些是顺着读的正文内容，折叠壳只会碍事。非查阅型的短表（≲5 行）更不用套 —— 壳比表还占地方。

**但上面两类必套表不受行数限制**：符号身份图例只有三四行时照样套。
理由是同类表行为必须一致 —— 读者收起过一次 notation 表之后，下一张 notation 表也该能收，
不能让他去猜「这张为什么收不了」。

**两份清单都是典型例子，不是封闭清单。** 清单没覆盖的表回到开头那句判据：
**回头查的套，顺着读的不套**；清单与判据打架时以判据为准。

写法：把原来的 `<h3>` / `<h4>` 标题**整个搬进 `<summary>`**，行数写进 `.cnt`。
标题标签留在 summary 里面，样式与语义都不用另配：

```html
<details class="fold" open>
  <summary><h3>编号对照表 <span class="cnt">· 15 行</span></h3></summary>
  <div class="tbl"> … </div>
</details>
```

- **`open` 必须写**，理由同 `.gloss`，见上一节末尾。
- 行数是收起后唯一的线索，必须写，且要和 `<tbody>` 的实际行数对上。
- 表的**附属说明**（缩写小字注 `p.small`、`box.warn` 的待核实声明）放进 `<details>` 里，
  跟着表一起收 —— 表没了，只留一条针对它的警告是错的。
- `summary` 上不加类名，样式由里面的 `h3` / `h4` 提供。

## 交付前自检（必做）

```python
from html.parser import HTMLParser
import re
VOID={'br','hr','img','meta','link','input'}
class P(HTMLParser):
    def __init__(s):
        super().__init__(); s.stack=[]; s.err=[]
    def handle_starttag(s,t,a):
        if t not in VOID: s.stack.append(t)
    def handle_endtag(s,t):
        if t in VOID: return
        if not s.stack: s.err.append(('extra',t)); return
        if s.stack[-1]!=t:
            s.err.append('expected %s got %s'%(s.stack[-1],t))
            for i in range(len(s.stack)-1,-1,-1):
                if s.stack[i]==t: del s.stack[i:]; return
        else: s.stack.pop()

t=open(FILE,encoding='utf-8').read(); p=P(); p.feed(t)
st=re.search(r'<style>(.*?)</style>',t,re.S).group(1)
bd=re.sub(r'<!--.*?-->','',t.split('</style>',1)[1],flags=re.S)    # 正文：剥掉 CSS 与注释
assert not p.err and not p.stack, p.err[:5]                        # 标签配平
assert st.count('{')==st.count('}')                                # CSS 配平
assert len(re.findall(r'Cascadia|Consolas|Menlo|monospace',t))==0   # 区块继承正文字体
assert t.count('src=')==0 and 'http' not in st                     # 样式自包含、无外部资源
assert len(re.findall(r'<details(?![^>]*\bopen\b)',bd))==0          # 折叠块一律默认展开
assert bd.count('<details')==bd.count('<summary')                  # 每个折叠块都有标题行
assert bd.count('<div class="gloss"')==0                           # 释义块必须是 details，不是旧的 div.gloss
```

**预期**：七条断言全过，无输出。任何一条不过就不要交付。

后三条只查 `bd`（剥掉 CSS 与注释的正文），因为注释里写给自己看的 `<details>` 示例不是真标签 ——
模板本身就是这么先挂掉一次的。第五条覆盖 `.gloss` 与 `.fold` 两种折叠块。

注：第四条只管**样式自包含**（`<style>` 里不得引外部资源、全文不得有 `src=`）；
正文里指向 DOI / 原文的 `<a href="https://…">` 是允许的。

### 式号回原文核对（必做，但不是断言）

七条断言过了之后再跑这一段，把笔记用到的式号逐个拿回原文文本层查：

```python
import re, sys
sys.stdout.reconfigure(encoding='utf-8')     # Windows 控制台常是 cp936/cp1252，不加这行中文 print 会崩

html = open(FILE, encoding='utf-8').read()
src  = re.sub(r'\s+', '', open(TXT, encoding='utf-8').read())    # TXT = 第 1 步抽出的全文

used = re.findall(r'<span[^>]*class="eqn"[^>]*>(.*?)</span>', html, re.S)
used = [re.sub(r'\s+', '', u) for u in used if u.strip()]        # 空 .eqn 是原文未编号，跳过
missing = sorted(set(u for u in used if u not in src))
print('式号 %d 个（去重 %d），原文未找到：%s' % (len(used), len(set(used)), missing or '无'))
```

两边都先剥掉所有空白再比，这样文本层把 `(1a)` 抽成 `( 1a )` 也能对上，
且不必假设原文的编号体系（`(2.14)`、`(A.3)` 一样能查）。

**预期**：`原文未找到：无`。第 1 步的 txt **要留到这步跑完再删**。

**这是打印清单，不是 assert。** 存在合法失配：有些期刊把式号排成矢量图形，文本层里根本没有它。
所以不阻断交付 —— 但凡列出来的号，交付前逐个交代：要么改对，要么在交付说明里写明
「(12) 未见于文本层，已回 PDF 目视确认」。**不许沉默放过。**

**它抓什么、不抓什么**：

- ✅ 写出**原文不存在**的号：凭空造号（原文只到 (18)，笔记写了 (23)）、
  原文用 (1a)(1b) 而笔记压成 (1)(2)。
- ❌ 写成原文**存在**的另一个号。两种形态，都查不出来：
  - **在已有编号范围内重排** —— 只讲了 (1)(2)(6)(7)(8) 却压成 (1)–(5) 时，(3)(4)(5) 在原文里都真实存在。
  - **转写错误** —— (7) 误作 (8)，而原文正好有 (8)。小号数几乎必然在文本层某处出现，基本抓不到。

  **别指望脚本兜住转写错误**，这一类只能靠上一节那条规则逐条照抄。

### 关于图片：默认不放，这是有意决策

第四条的 `src=` 是**全禁**，连 base64 内嵌（`<img src="data:image/png;base64,…">`）也一并禁掉了。
**这是有意的，不是漏网的 bug**，不要"顺手修好"：笔记定位是纯文字，靠 `.dgm` 盒子和表格转述图里的信息，
文件因此稳定在几十 KB。

**例外：用户明确要求配图时**（"把系统拓扑图放进来"这类）就放开，放几张、放哪些、怎么抽，
按用户说的办 —— 这里不预设规则。只有两件事是机械上绕不开的：

- 第四条断言换成下面这条（否则有图必然过不了自检、交付不了）：

  ```python
  assert not re.findall(r'src="(?!data:)', t) and 'http' not in st
  ```

- base64 用脚本注入（PyMuPDF 抽图 → Python `b64encode` → 写进 HTML），模型不要自己打：
  一张 200 KB 的图 base64 后约 27 万字符 ≈ 7 万 token，逐字输出既贵又会出错。

## 对比度检查（**改过色值才需要**）

判据：**35 项全部 ≥ 4.5:1**。配对清单——
正文/背景、次要文字/背景、次要文字/公式块底、强调色/背景、
正文/四种高亮底（各自叠在 `--bg` / `--card` / `--code-bg` 三种底上，共 12 项）、
正文/（提示框底 ×4、目录底、条纹行底、高亮行底、直觉块底、术语表底、表头底）、
三类提示框标题/各自底、六个徽章文字/各自底。

两个非显然的坑：

1. 徽章是 15px 粗体，**不属 WCAG「大字号」**（粗体需 18.66px 才算），所以适用 4.5:1 而非 3:1。
2. 提示框标题的浅底由主色派生，**压暗主色后浅底也会变，必须重算浅底再检查**（迭代到收敛）。

不达标时按「保持色相、逐步压暗」修正。
